01 / CHOOSE AN ASSET

Start in Catalog.

In a workspace, use Catalog → New Asset. Choose the asset type that matches your policy and give it a meaningful name.

Decision Table

Use rows when a policy maps combinations of conditions to results. The first matching row wins.

Decision Tree

Use branching conditions when a policy needs a visible sequence of checks and result leaves.

Flow

Use a canvas to combine request transformations, decisions, lookups, and branching.

02 / DEFINE THE CONTRACT

Describe the data first.

Open Data Contract to declare the asset’s Inputs and Outputs. Define field types, required status, and examples. Fields and Schema views represent the same asset-owned contract.

  • Inputs describe the incoming request data.
  • Outputs describe a successful response.
  • Variables hold intermediate values in a Flow. Declaring a Variable does not initialize it; a step must produce its value.
Example: Order Shipping Policy

Declare numeric Input subtotal. Declare numeric Output fee and string Output method. The policy returns free Standard shipping at a subtotal of 100 or above; otherwise the fee is 9.

03 / BUILD THE LOGIC

Connect the request to its response.

Open Design. In a Flow, add steps from the palette, connect their order, and configure each step. In a Table or Tree, bind conditions and results to that asset’s declared fields.

1

Prepare the request. Validate fields, set values, or use expressions. Choose Fields controls the fields retained in the document.

2

Work with lists. Transform items, filter or flatten lists, summarize values, and check whether items meet a condition.

3

Invoke a decision. Choose a published Table or Tree version, map its Inputs, select the result object, and assign it to a declared object Variable.

4

Branch and return. Configure If / Else paths and prepare the output fields for each endpoint.

For calculations, the expression editor offers Visual and Advanced JSON modes. Each mode keeps its own content; the selected mode supplies the saved expression.

04 / ADD REFERENCE DATA

Keep lookup values outside the policy.

Open Reference Data, create a dataset, import an .xlsx worksheet, and select a unique primary key. Review the inferred columns, save the draft, and publish a version.

Back in a Flow, add a lookup and select the dataset’s published version. Map a lookup key and choose an object Variable for the result. Set whether a missing record should stop the Flow or continue with null.

Import scope

Current imports support primitive string, number, and boolean columns, up to 5 MB, 5,000 rows, and 100 columns. Formula cells, merged cells, and duplicate or empty primary keys are rejected. Import replaces the draft’s schema and rows.

05 / INSPECT AND VALIDATE

Review the design before publishing.

Use Validate to inspect authoring issues. In a Flow, use Run to open Test Input, paste a request object, and select Run test. The panel includes Result, Trace, and Issues, with links back to affected steps.

06 / PUBLISH A VERSION

Make changes explicit.

Save Draft persists both the contract and the visual definition. Save incomplete work as you author, resolve validation errors, and then publish the saved revision. Publish does not save unsaved changes automatically.

Draft→ Save & validate →Published v1→ Edit →New draft

Publication creates an immutable snapshot and removes the active draft. The editor shows the publication read-only. Edit explicitly starts a new draft; publishing again creates another version.

WORKED EXAMPLE

Order fulfillment, end to end.

The sample workspace contains an Order Fulfillment Flow, a published Order Shipping Policy Table, an Order Review Policy Tree, and published regional handling fees.

SHIPPING TABLESubtotal ≥ 100 → fee 0

Otherwise fee 9. Method: Standard.

REVIEW TREERestricted or subtotal > 500

Require review; otherwise approve.

REFERENCE DATACA: 2 · US: 4 · GB: 6

Regional handling fee. Unknown country stops the Flow.

The Flow flattens warehouse shipments, keeps active positive-quantity items, calculates line totals, and sums the full subtotal. It checks for restricted goods before ranking and trimming the packing list to three priority lines.

Shipping and review use the full subtotal. The top-three total is a separate packing metric, priorityValue, not the payable subtotal.

COMMON QUESTIONS

A few things to know.

Does organisation membership grant every workspace? +

No. Invite people through Organisations → Members. Once accepted, assign each person to the appropriate workspace as Reader, Editor, or Admin. Organisation membership and workspace access are separate.

Is a MongoDB database required? +

The Java engine architecture uses MongoDB 6.0 as a syntax and behavior reference for its supported expression subset, without requiring a MongoDB database.

Can I use a draft as a called decision? +

Decision Table and Decision Tree steps select explicit published versions. Save and publish the called asset before configuring it in a Flow. Drafts are not invocation targets.
